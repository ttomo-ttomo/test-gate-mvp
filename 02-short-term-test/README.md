# 短期テスト（1〜2週間）

> 1機能・1PRで、簡易リスク評価からテスト生成・実行、分岐カバレッジ、ミューテーション、欠陥注入までを小さく通す検証実験。全体像は [../README.md](../README.md)。

## 読むもの

| ファイル | 内容 |
| --- | --- |
| [WORKFLOW.md](WORKFLOW.md) | 5工程の手順・完了条件・結果の記録様式（**手順の正本**） |
| [PROMPTS.md](PROMPTS.md) | Claude Code に1工程ずつ渡すプロンプト |

まず WORKFLOW.md を読み、実施時に PROMPTS.md を使う。工程表と手順はここに書かない。

## 優先順位の考え方

時間が限られる場合は、**受入条件から実行可能なテストを作り、実際に検証できる状態にすることを優先する**。ただし受入条件に載っていない重大な故障を見落とさないよう、最初に簡易リスク評価だけ行う。本格的なリスク評価やテスト計画の整備を先に完成させない。

- 簡易リスク評価は最初の30分〜1時間で重要故障と対象を仮決めする。正式なリスク評価表の整備は対象外。
- まず1機能・少数の受入条件でテストの生成から実行までを通す。実行できないテストを大量に作らない。
- 受入条件にない重大故障（セキュリティ等）はテスト生成だけでは拾えない。リスク評価で見つけたものは対象条件の追加・確認につなげる。
- 後半の検証は時間不足なら対象を絞り、結果と未実施範囲を明記する。カバレッジやミューテーションの数値だけで品質を保証したとは扱わない。
